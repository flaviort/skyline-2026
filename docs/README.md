# Skyline 2026 docs

Everything about this project lives in this folder: product, plan, specs, architecture, reference research, content and (after the homepage is built) the design system.

| File | What it is | Read it when |
|---|---|---|
| [STATUS.md](STATUS.md) | Handoff: where the project stands, next steps, what is missing | Start of every session |
| [PLAN.md](PLAN.md) | Build order, status of every part, approval gates, decisions, the per-part workflow with impeccable | Always first |
| [PRODUCT.md](PRODUCT.md) | Who the site is for, what Skyline is, facts we can claim, brand commitments | Writing copy, making product calls |
| [specs/](specs/README.md) | One spec per part (homepage) and per page (internal pages) | Before building or reviewing any part |
| [ARCHITECTURE.md](ARCHITECTURE.md) | Stack, folders, static content, component library, code rules | Before writing code |
| [REFERENCE.md](REFERENCE.md) | Measured teardown of extrafazant.nl: scaling, color, type, motion | Matching the reference |
| [CONTENT.md](CONTENT.md) | Copy deck, project inventory, asset list, placeholder register | Copy and assets |
| [NOVA-3D.md](NOVA-3D.md) | The rigged Nova model: inspection results, fix list for the 3D designer, pipeline | Working on Nova, talking to the designer |
| DESIGN.md | The design system, written from the finished homepage | After part 11 |

Root files kept outside `docs/` on purpose: `CLAUDE.md` and `AGENTS.md` (read by coding agents at the root) and `README.md` (the repo's front page). Tool state lives in `.impeccable/`.
